+     The prebuilt React Native `CopilotChat` does not draw surfaces yet, so the chat is your own list. Each surface arrives as an activity message in `agent.messages`; `GenerativeUIActivity` draws it.
+     A failed run does not reject: `copilotkit.runAgent` resolves, and the error goes to the `onError` subscribers of the core. This helper listens, while the run lasts, for an error of its agent that ends the run; a failed tool call does not end it, so the helper ignores those. On failure it takes back the messages that the turn added, such as the user message and any partial reply. It keeps the surfaces of the run, in the chat and in a [named area](/langgraph-typescript/generative-ui/components/surfaces) alike: the provider never forgets a surface, the model still sees it on its next run, and the runtime rejects a new `createSurface` with its id, so removing its activity message would only hide it. The take-back is local: a runtime that stores the thread may still have the user message, and connecting to that thread again brings it back. The helper counts every run failure of its agent while it waits, so start one run of an agent at a time.
+     ```tsx title="src/agentTurns.ts"
+       CopilotKitCoreErrorCode,
+       type useAgent,
+       type useCopilotKit,
+     } from "@copilotkit/react-native/headless";
+       isGenerativeUIActivity,
+       type GenerativeUIActivityMessage,
+     type CopilotKit = ReturnType<typeof useCopilotKit>["copilotkit"];
+     type Agent = ReturnType<typeof useAgent>["agent"];
+     /**
+      * The errors that end a run. A failed tool call is not one of them
+      * (TOOL_HANDLER_FAILED, TOOL_ARGUMENT_PARSE_FAILED): its error goes back to
+      * the model as the result of the call, and the run goes on.
+      */
+     const RUN_FAILURES: ReadonlySet<CopilotKitCoreErrorCode> = new Set([
+       CopilotKitCoreErrorCode.AGENT_RUN_FAILED,
+       CopilotKitCoreErrorCode.AGENT_RUN_FAILED_EVENT,
+       CopilotKitCoreErrorCode.AGENT_RUN_ERROR_EVENT,
+       CopilotKitCoreErrorCode.AGENT_THREAD_LOCKED,
+     ]);
+     // Date.now() alone repeats within a millisecond; with a counter, ids do not.
+     let sent = 0;
+      * Sends one user message and runs the agent. Resolves with the run's error,
+      * or undefined; it never rejects. It counts every run failure of this agent
+      * while it waits, so start one run of an agent at a time.
+     export async function runTurn(
+       copilotkit: CopilotKit,
+       agent: Agent,
+       content: string,
+     ) {
+       const before = agent.messages.map((message) => message.id);
+       const { threadId } = agent;
+       let failure: Error | undefined;
+       const subscription = copilotkit.subscribe({
+         onError: ({ error, code, context }) => {
+           if (context.agentId === agent.agentId && RUN_FAILURES.has(code)) {
+             failure ??= error;
+           }
+       });
+       try {
+         sent += 1;
+         agent.addMessage({
+           id: `user-${Date.now()}-${sent}`,
+           role: "user",
+           content,
+         await copilotkit.runAgent({ agent });
+       } catch (error) {
+         failure ??= error instanceof Error ? error : new Error(String(error));
+       } finally {
+         subscription.unsubscribe();
+       }
+         if (failure) takeBack(agent, before, threadId);
+         console.error("Could not take the failed turn back:", error);
+       return failure;
+      * Removes the messages added since `before` (their ids), such as the user
+      * message and a partial reply. It keeps the surfaces: the provider keeps
+      * every surface that a run rendered, and the model still sees it, so the
+      * screen shows it too.
+     export function takeBack(
+       before: readonly string[],
+       threadId: string | undefined,
+       // The agent moved to another thread: those messages are not this turn's.
+       if (agent.threadId !== threadId) return;
+       const kept = new Set(before);
+       agent.setMessages(
+         agent.messages.filter(
+           (message) => kept.has(message.id) || isGenerativeUIActivity(message),
+         ),
+      * An activity message that GenerativeUIActivity draws: its surface is aimed at
+      * the chat (the target it shows) and the agent has not deleted it.
+     export function isChatSurface(message: GenerativeUIActivityMessage) {
+       if (!isGenerativeUIActivity(message)) return false;
+       const content = message.content as {
+         target?: unknown;
+         operations?: unknown;
+       } | null;
+       const operations = Array.isArray(content?.operations)
+         ? content.operations
+         : [];
+         content?.target === "chat" &&
+         !operations.some(
+           (op) => typeof op === "object" && op !== null && "deleteSurface" in op,
+         )

+     The error line shows the error of a run that `send` started. The same error reaches the `onError` of `CopilotKitProvider`; without that prop it is only logged with `console.error`, which nobody sees in a release build, so pass `onError` and send it to your crash reporter. A run that a click on a surface starts ([Send a click to the agent](/langgraph-typescript/generative-ui/components/state-and-actions#send-a-click-to-the-agent)) does not go through `runTurn`: its user message stays when it fails, and its error reaches only that `onError`. While a run of this agent is going, one that `send` started or one that a click on a surface started, Send is disabled; a run of another agent does not disable it. A ref, set at once, keeps a second tap that lands before the next render from sending twice.
+     Like the web chat, `GenerativeUIActivity` shows only surfaces aimed at the chat, so a surface that the agent aims at a [named area](/langgraph-typescript/generative-ui/components/surfaces) renders there and not in the list. The chat target is always offered to the agent, so an app that shows surfaces only through `GenerativeUISurface`, or only in the prebuilt `CopilotChat`, never shows a surface aimed at the chat. `GenerativeUIActivity` renders nothing without a `GenerativeUIProvider` above it, or under a provider without `ui`, and warns in development, once for each distinct cause; it also renders nothing for a deleted surface, which `isChatSurface` leaves out of the list.

+ Inspector runs in the browser, so it has no React Native version. On React Native, pass `errorBoundary={{ onError }}` to `GenerativeUIProvider`: it reports render failures, invalid props, failed events, failed functions that a component called and operations that the app rejected, with the surface. Operations that the runtime rejected never reach `onError`. They reach the `rejected` and `error` props of the `Wrapper` (with the ones that the app rejected): the `Wrapper` of `GenerativeUIActivity` for a chat surface, and the `Wrapper` of `GenerativeUISurface` for a surface in a named area. Both default wrappers show a short error line. The exception is a rejected `createSurface`. A named area then keeps its fallback and renders no `Wrapper`; when the app rejected it, `onError` gets it and `<GenerativeUIActivity target="<id>">` shows it. When the runtime rejected it, no activity message is sent for it, so only the model learns of it, in the result of its `render_ui` call, and nothing on the device shows it. The one exception is a `createSurface` with the id of a live surface: the runtime adds that rejection to the live surface, whose `Wrapper` shows it. See [Errors on the device](/langgraph-typescript/react-native#errors-on-the-device).
